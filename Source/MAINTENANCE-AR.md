# دليل صيانة موقع مركز وائل حداد

هذا هو مرجع العمل الأساسي لأي مطور يبدأ من نسخة المستودع. يصف السلوك الحالي والقرارات التي يجب الحفاظ عليها، حتى لو لم يتوفر سجل العمل المحلي أو لقطات المعاينة. آخر تحديث لهذا المرجع: 25 تشرين الأول 2026.

## أين نعدل

`Source/` هو المصدر المعتمد للموقع. عدّل ملفات الموقع فيه فقط، ثم أعد توليد النسخ المشتقة. لا تعدّل `Demo/` أو مجلد التسليم أو ملفات ZIP يدوياً؛ أي تعديل فيها سيضيع عند التغليف التالي.

| الملف داخل `Source/` | المسؤولية |
|---|---|
| `index.html` | نقطة الدخول، بيانات الصفحة، الخطوط، وترتيب تحميل `data.js` ثم `app.js` ثم `admin.js`. |
| `data.js` | الإعدادات والمحتوى والخدمات والأعراض والمراحل والتعليقات، ثم البيانات التجريبية تحت `sample`. |
| `hood-motion.js` | تركيب صورة الجسم الأصلية الثابتة مع إطارات الغطاء والمحرك الشفافة داخل Canvas، ورسم الدخان المتزامن، وتثبيت النهاية وإدارة الإلغاء والبدائل. |
| `app.js` | القالب المشترك، التنقل، الحجز، الأعراض، التتبع، التقارير، سجل السيارة، التخزين، وإضاءة الواجهة. |
| `admin.js` | لوحة التحكم التجريبية وشاشة الميكانيكي؛ تستخدم الوظائف المشتركة التي يتيحها `app.js`. |
| `styles.css` | التصميم المتجاوب، العربية والإنجليزية، الألوان، وشريط الموبايل وحركة المصابيح. |
| `assets/` | صور التشغيل والشعارات والأيقونة. |
| `tools/package-store.sh` | إنشاء العرض وملفات الرفع والمصدر والتسليم والتحقق منها. |
| `tools/render-car-frames.py` و`tools/car-hood-calibration.json` | إخراج إطارات الغطاء والمحرك محلياً من الفيديو المرجعي فوق صورة الجسم الأصلية الملائمة لمنظوره؛ لا تعمل هذه الأدوات في المتصفح أو أثناء التغليف العادي. |
| `tools/delivery-README-AR.md` | قالب دليل التسليم. |
| `tests/` | الاختبارات القابلة للتشغيل؛ راجع [دليل الاختبارات](tests/README.md). |

اقرأ الملفات من القرص مجدداً قبل تعديلها، خصوصاً عند العمل بالتوازي. وثّق أي تغيير في السلوك أو المحتوى المعتمد هنا أو في المستند المناسب، ولا تعتمد على سجل محادثة غير موجود في المستودع.

## المعاينة المحلية

الموقع HTML وCSS وJavaScript عادي، بلا خطوة بناء وبلا سيرفر تطبيق. من جذر المشروع:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory Source
```

افتح `http://127.0.0.1:8765/`. تتطلب هذه الطريقة Python 3. ويمكن فتح `Source/index.html` مباشرة لمعاينة سريعة، لكن استخدم HTTP للفحوص ولثبات سلوك المتصفح. على الماك، يفتح `START-DEMO.command` العرض المولّد إن وجد، وإلا يفتح المصدر.

الخطوط تُحمّل من Google Fonts؛ عند غياب الإنترنت يستخدم المتصفح خطوط الجهاز. النص العريض داخل شريط العرض لا يوسّع صندوق السطر أثناء تحميل وزن الخط، لمنع انزياح الصفحة والسيارة بكسلًا واحدًا. الصور والشعارات اللازمة للتشغيل محلية. أوامر الاختبار وإعداد المتصفح موثقة في `tests/README.md`؛ لا تضف مسارات خاصة بجهاز معين إلى الاختبارات أو الأدلة العامة.

## التغليف والتسليم

من جذر المشروع شغّل:

```sh
bash Source/tools/package-store.sh
```

أو شغّل `UPDATE-PACKAGE.command` على الماك. يحتاج السكربت Bash و`zip` و`unzip`؛ ويفحص صياغة ملفات JavaScript أيضاً إذا توفر Node.js.

المخرجات مشتقة من المصدر:

- `Demo/`: عرض محلي مع البيانات التجريبية.
- `wael-haddad-hostinger-upload.zip`: ملفات الموقع العام، و`index.html` في جذر الأرشيف.
- `WaelHaddad-website-source.zip`: مصدر قابل للصيانة.
- `WaelHaddad-complete-with-demo/` و`WaelHaddad-complete-with-demo.zip`: التسليم الكامل الذي يحتوي النسخ السابقة وأدلتها.

يوضع أرشيفا الرفع والمصدر داخل بنية التسليم. راجع رسالة النجاح النهائية للسكربت بدلاً من افتراض وجودهما في جذر المشروع. ملفات التشغيل المعتمدة محددة في مصفوفة `RUNTIME`؛ عند إضافة أصل مطلوب في المتصفح أضفه إلى تلك القائمة أيضاً.

على الماك يخفي السكربت الملفات الداخلية بعَلَم Finder، ليبقى مجلد التسليم وملف ZIP الكامل ظاهرين. هذا لا يحذف الملفات ولا يمنع قراءتها. يمكن إظهار الملفات المخفية بواسطة `Cmd+Shift+.`. الملفات المولّدة والمخرجات المؤقتة لا تُرفع إلى المستودع؛ يمكن إعادة إنتاجها من المصدر. صورة أجزاء الجسم الثابتة وأطالس طبقات المقدمة الشفافة وصورتا الفتح والإغلاق هي أصول الواجهة؛ الصورة المغلقة المركبة تكفي للعرض الثابت عند تعذر التشغيل. حزمة المصدر تتضمن صورة الاستوديو الأصلية وصورة الجسم الملائمة لمنظور الفيديو بصيغة WebP وأطلس الإطارات المرجعي `hood-reference.webp` وسكربت إخراج الإطارات ومعايرته لإعادة إنتاج أصول التشغيل محلياً. النسخة الأصلية PNG عالية الجودة اختيارية؛ لا تحتاجها حزمة التشغيل العامة.

## الفرق بين العرض والموقع العام

يجب أن يبقى هذا السطر في `data.js` بالحروف والمسافات نفسها:

```js
  mode: 'demo',
```

سكربت التغليف يحوّله إلى `live` في نسخة الرفع فقط. لا تغيّر المصدر إلى `live` لتجهيز تسليم.

| الحالة | `demo` | `live` |
|---|---|---|
| الخدمات والعرض والأعراض والتواصل والحجز | متاحة | متاحة |
| أمثلة السيارات والحجوزات وسجل الصيانة | تُنشأ من `sample` وتُعلّم بأنها أمثلة | لا تُنشأ في الحالة التشغيلية ولا تظهر في الواجهة |
| التتبع والتقارير والسجل والأدمن والميكانيكي | تجربة محلية | المسارات محجوبة |
| التخزين | `localStorage` بالمفتاح `wh-demo-v1` | تخزين المتصفح بالمفتاح المنفصل `wh-live-v1` |
| وصول الطلب إلى المركز | يحتاج المستخدم إرسال رسالة واتساب | يحتاج المستخدم إرسال رسالة واتساب |

إخفاء صفحات العرض في `live` ليس نظام صلاحيات أو حماية بيانات. البيانات تحت `sample` أمثلة عامة وليست سجلات زبائن حقيقية؛ لا تضع أي سجل حقيقي أو سر داخل JavaScript. لا تعتمد على حجب المسارات لإخفاء محتوى الملف المصدر.

لوحة التحكم بلا كلمة سر في العرض، وتعديلات الأسعار والخدمات والحجوزات والموافقات تبقى في ذلك المتصفح. تغيير بيانات `data.js` لا يضمن استبدال إعدادات محفوظة سابقاً في `localStorage`؛ عند التحقق من القيم الافتراضية استخدم سياق متصفح جديداً أو إعادة ضبط بيانات العرض. يدعم الكود فشل التخزين أو حظره، ويعرض رسالة داخل الصفحة عند تعذر الحفظ.

## الحجز وواتساب: ثوابت وظيفية

الحجز ينتهي بصفحة تلخيص وزر يفتح رابطاً من الشكل `https://wa.me/962...` مع رسالة جاهزة يُرمّز نصها داخل الرابط وتحتوي تفاصيل الطلب. الرقم الافتراضي حالياً `0795866455`، ويتحول إلى `962795866455` في الرابط. إنشاء الطلب في المتصفح أو فتح صفحة التلخيص لا يرسل رسالة تلقائياً؛ المستخدم يرسلها من واتساب، والمركز يؤكد الموعد بالرد. لا يوجد استقبال مركزي للحجوزات في النسخة الحالية.

**لا تُعد رسم زر تثبيت الحجز أثناء الكتابة.** مع أحداث `input` و`change` تُحدّث المسودة و`#sum-body` فقط. إعادة بناء النموذج أو ملخصه الكامل قد تستبدل الزر بين نهاية الكتابة ولمسة الإرسال، فتضيع اللمسة. حافظ على هذا السلوك عند إضافة تحقق أو حقول أو تحسينات للملخص.

- الأرقام العربية `٠١٢٣٤٥٦٧٨٩` والفارسية `۰۱۲۳۴۵۶۷۸۹` تُطبّع إلى أرقام عادية.
- أرقام الجوال الأردنية المقبولة تطابق `^07[789]\d{7}$` بعد التطبيع. يدعم التطبيع بادئتي `962` و`00962`.
- بحث اللوحة يستخدم الأرقام بعد إزالة الفواصل والمسافات والعلامات، لذلك يجب أن يتطابق الإدخال بالأرقام العربية مع اللوحة التجريبية نفسها.
- أنشئ روابط الأجزاء دون شرطة مائلة: `#book` و`#book-svc-oil` و`#book-sym-brakes` و`#report-J1024` و`#job-J1024`. هذا يحافظ على الروابط العميقة في الاستضافات التي تغيّر `/` داخل الجزء.
- التأكيدات والأخطاء داخل الصفحة. لا تستخدم `alert()` أو `confirm()` أو `prompt()`.
- حافظ على فصل اختيار العَرَض `brakes` عن نص تسميته؛ تغيير الاسم الظاهر لا يغيّر المعرّف أو مستوى الاستعجال أو النصيحة.

## اللغة والاتجاه والمظهر

العربية هي الافتراضية باتجاه RTL، والإنجليزية متاحة من زر اللغة باتجاه LTR. اختيار اللغة محفوظ بالمفتاح `wh-lang`. يستخدم `app.js` الدالتين `tr(ar, en)` للنصوص و`L(object, key)` للحقول المنتهية بـ`Ar` و`En`. حافظ على تعيين `lang` و`dir` على عنصر `html` عند إعادة الرسم.

المظهر يتبع `prefers-color-scheme`، وتدعم CSS أيضاً تعيين `data-theme="light"` أو `data-theme="dark"` على الجذر. لوحة الموقع بني دافئ وبيج: الواجهة الأولى بني شوكولاتة `#302118` في المظهرين، مع نص وأزرار كريمية؛ بقية الأقسام بيج رملي وأسْطح كريمية في الفاتح، وبني داكن وأسْطح جوزية ونص بيج في الغامق. متغيرات `--bg` و`--surface` و`--sunk` تضبط الأقسام والبطاقات والنماذج؛ ومتغيرات `--hero-*` تضبط لون الواجهة ونصوصها وأزرارها. لا تصبغ جسم السيارة أو الشعارات أو طبقة LED بفلاتر الألوان عند تعديل اللوحة. اختبر اللغتين والمظهرين، ولا تفترض أن تغيير اللون يؤثر فقط في العربية.

الأسماء في صف الماركات إنجليزية في اللغتين، بالترتيب `Audi` ثم `Volkswagen` ثم `Porsche`، مع شعار كل اسم. القائمة `.hero-specialism` لها `dir="ltr"`؛ لا تعكس ترتيب العناصر مع RTL. صور الشعارات لها `alt=""` لأن الاسم مكتوب بجانبها، لتجنب تكراره لقارئ الشاشة. لا تضف مقدمة «متخصصين» أو `Specialists` إلى هذا الصف.

ملفات الشعارات الرسمية محفوظة كما هي في المصدر؛ يعرض شعار Audi بإنهاء كروم معدني ثلاثي الأبعاد وشعار Volkswagen بالقاعدة الدائرية الزرقاء الملكية والكروم الأصليين مباشرة فوق الخلفية البنية، ويحتفظ شعار Porsche بألوان درعه الأصلية دون فلاتر. العناوين فوق الأسطح الداكنة بلون شامبانيا دافئ `#E8CFA4` مع لمعة معدنية هادئة، والعنوان الفرعي في الواجهة بلاتيني ناعم `#DDD4C7` والنص الثانوي `#CFC8BE`؛ عناوين الأسطح البيج في الوضع الفاتح تبقى برونزية داكنة للتباين. خلفية السيارة تتضمن هالة إضاءة دافئة في `.hero-visual::before`؛ تُرسم إضاءة المصابيح في طبقتين فوق وضعية الإغلاق الثابتة، وتضم الصورة البديلة التركيب نفسه. صور السيارة وطبقات الغطاء شفافة خارج حدودها، وتظهر خلفها ألوان الموقع نفسها دون مستطيل. أرضية الاستوديو الأصلية وانعكاسها في `.rs5-floor`، بصورة مستقلة ذات حواف شفافة، أسفل السيارة مباشرة؛ يضيف الظل الناعم في `.hero-car::before` تماس العجلات. الخطوط والأحجام وتوزيع النص لم تتغير.

## الواجهة الأولى وحركة غطاء السيارة

السيارة صورة توضيحية وليست توثيقاً لسيارة زبون أو تجهيزات المركز. جسم السيارة كله من صورة الاستوديو الأولى الواضحة، بما فيه السقف والزجاج والمصابيح والرفارف والشبك وحلقاتAudiوشارةRS5والصدام والباب والعجلات وتجاويفها والخلف. تُلائم هذه الصورة مرة واحدة بتحويل منظور عام واحد، وتظل جميع أجزائها ثابتة طوال الإغلاق؛ لا يوجد تدفق بصري أو شد موضعي للباب أو العجلات أو مقدمة السيارة. أُعيدت حدود الإطارات والصدام والخلف من الصورة نفسها بدلاً من إبقاء قص ناقص من الفيديو. الأرضية المصورة وانعكاسها يستخدمان التحويل العام نفسه ليتوافقا مع العجلات.

الغطاء الحقيقي وحجرة المحرك والمفصلة فقط من الفيديو السابق. أقنعة إعداد محلية تتبع حدود الغطاء المصورة عبر التسلسل، مع منطقة حجرة المحرك في موضع الفتحة؛ لا تُحرَّك صورة غطاء مغلق بمضلعCSS، ولا تُنقل المصابيح أو قاعدة الزجاج والرفارف من الفيديو. تُمسح مساحة الغطاء المغلق الحقيقية من قاعدة الصورة قبل تركيب الحركة، فلا يظهر غطاء ثانٍ خلف الحجرة. بعد قفل الغطاء تُثبت الوضعية46؛ تظهر شرائطLEDأولاً ثم إضاءة المصابيح الرئيسية فوق المصابيح الأصلية الثابتة، دون استبدال جسم السيارة بإطار لاحق. مصدر التوهج الرئيسي فرق الإضاءة الموجب من الفيديو بعد محاذاته للمصابيح الأصلية، وتثبت هذه النهاية دائماً.

حُسن وضوح بكسلات الغطاء والمحرك محلياً، لكن أصلها فيديو بعرض720px، وليس تصويراً جديداً عالي الدقة. قد تبقى فروق في الملمس من الفيديو؛ لا تثبت فحوص التشغيل وحدها واقعية اتصال الغطاء، ولذلك تلزم مراجعة التسلسل بصرياً. لا يحتاج التشغيل إلى قصCSSأو مجسم أو إعادة إسقاط هندسي داخل المتصفح؛ الإسقاط الوحيد للجسم ثابت ومُعد مسبقاً.

### إعادة إخراج الإطارات محلياً

`tools/render-car-frames.py` يقرأ `tools/car-hood-calibration.json` وصورة `assets/car-body-aligned.webp` وأطلس `assets/hood-reference.webp`. صورة الجسم الشفافة1080×600 مدخل محضر من أصل الاستوديو1672×941 بتحويل منظور عام واحد، مع استعادة حدود الإطارات والصدام والخلف من الأصل نفسه دون تدفق بصري أو تعديل موضعي للهيكل. هذه الملاءمة خطوة تحضير سابقة؛ لا يعاد حسابها لكل إطار. أصل الاستوديو`assets/coupe-studio.webp`محفوظ في المصدر أيضاً، لكن إعادة إخراج أصول التشغيل تستخدم الجسم المحضر.

تحتاج إعادة إخراج الإطارات فقط إلىPython3معPillow. هذه تبعية تحضير محلية اختيارية، لا تُشحن في الموقع ولا تحتاجها عملية التغليف العادية. من جذر المشروع:

يمكن تحديد مجلد مخرجات بواسطة`--output /absolute/path/to/output`، ومجلد مراجعة بواسطة`--review /absolute/path/to/review`. الخيار`--reference-frames /absolute/path/to/frames`يستورد48إطارPNGمحضراً بأسماء001.pngإلى048.pngبدلاً من أطلس المرجع المضمن؛ الاستعمال العادي لا يحتاج الملفات المحلية السابقة. مدخلات إعادة الإخراج المضمنة1080×600. يظل أصلPNGالقديم اختيارياً. عند تعديل المعايرة راجع الفتح وتسع وضعيات إغلاق والنهاية، واتصال المفصلات بالحجرة وحافة الغطاء مع الرفارف، وثبات المصابيح والسقف والزجاج والعجلات والباب وحدود الجسم. لا يحتاج التحضير إلى خدمة فيديو خارجية.

`heroCar()` يحتفظ بإطار ثابت بنسبة720/400. على الكمبيوتر بعرض1101pxفأكثر، يمتد إلى110%من عمود الصورة مع هامش−5%لإعادة حجم السيارة الكبير القديم؛ عند1366pxيبلغ الإطار نحو844px. في النطاق761..1100pxيملأ العمود دون حد520px، وعلى الموبايل حتى760pxيبقى عرضه100%وبحد أقصى520px. لا تتغير شبكة النصوص أو تخطيط الموبايل. صورة`.rs5-floor`المطلقة تشغل الإطار نفسه خلف السيارة، فلا تتحرك الأرضية أثناء الإغلاق. مصدر`rs5SourceVideo`مخفي بصرياً بحجم1pxوليسdisplay:none؛ يرسم`rs5HeroCanvas`القاعدة الثابتة ثم خلية الغطاء والمحرك المحددة بالتوقيت، ثم طبقتي الضوء عندما يحين دورهما. لا يوجد تحريك أو تلاشي لعنصر السيارة أو قناع على إطاره؛ الظل الأرضيCSSمستقل. صور التحضير وأطلس المرجع لا تدخلRUNTIME؛ الأرضية والقاعدة والأطالس المخرجة وطبقتا الضوء هي الصور المطلوبة وقت التشغيل.

تضيف طبقةCanvasشفافة مستقلة `.rs5-smoke` دخاناً خفيفاً من منطقة المحرك أثناء الإغلاق. هذا مؤثر مرسوم محلياً بالكود، مستوحى من المقطع المرجعي، وليس بكسلات دخان مقتصة منه. تُحضّر أربع صور كثافة صغيرة مرة واحدة وتُرسم منها16نفثة بمواقع وشفافية محسوبتين من ساعة الحركة نفسها. تمتد الطبقة240px فوق إطار السيارة بمقياس الرسم1080×600. يرتفع الدخان ببطء نسبياً ويتلاشى مع انغلاق الغطاء: ينتهي بعد0.4s من لحظة القفل (`latchAt`)، فلا تبقى سحابة عائمة فوق غطاء مغلق. تكون الطبقة فارغة عند البداية وعند مرحلةLED، وتُمسح وتُحرر صورها عند الإكمال أو الفشل أو الإلغاء، ولا تظهر عند تقليل الحركة.

`startHeroLights()` يحتفظ باسمه لتوافق بقية التطبيق. `WHHood.create()` ينتظر فك القاعدة والأطالس الأربعة وطبقتيLEDوالمصابيح، ثم يعرض الفتح المركب؛ لا يظهر إطار مغلق ثم يقفز للفتح. عند ظهور55% من الإطار عبر IntersectionObserver، ينتظر300ms مرئية ثم تبدأ ساعة زمنية مستقلة على requestAnimationFrame وperformance.now (منذ إصدار `20261027-motion` لا يوجد عنصر فيديو؛ كان حظر التشغيل التلقائي، مثل وضع توفير الطاقة على iPhone أو متصفحات بلا H.264، يُسقط الحركة كلها إلى الصورة الثابتة). الإعدادات في `app.js`: `closeAt` بداية الإغلاق، `latchAt` لحظة القفل (1.2s)، `ledAt` (2.15s)، `headlightsAt` (2.85s)، `duration` (3.5s)، و`progress` جدول تقدم الإغلاق المقاس لكل وضعية مصورة0..46 (من مركز ثقل قناع الغطاء والمحرك). الغطاء يتبع منحنى سقوط: يبدأ ببطء كأن اليد تتركه ثم يتسارع بالجاذبية حتى القفل، ثم ارتداد صغير (تقدم يرجع ~2.8%) خلال0.3s. الوضعية المعروضة كسرية بين خليتين متجاورتين وتُمزجان خطياً (جمع premultiplied بعملية `lighter` على Canvas جانبي)، فتتحرك تسجيلات24fps بنعومة على شاشات60–120Hz. بعد القفل تنضغط السيارة على تعليقها: إزاحة رأسية مخمدة داخل Canvas حتى ~2.3px بمقياس1080 تعود إلى الصفر تماماً قبل1.9s؛ الأرضية المصورة لا تتحرك فيظهر الانضغاط بالنسبة لها، وموقع عنصر Canvas نفسه ثابت. عند2.15s تضيء شرائطLED من طرفها الداخلي نحو الخارج خلال0.42s بحافة ناعمة (`ledSweeps`)، مع تقوية مؤقتة لوضوح المرحلة تختفي مع المصابيح الرئيسية. عند2.85s تشتعل المصابيح الرئيسية كالزينون: ومضة قصيرة ثم خفوت ثم صعود ناعم للكامل خلال ~0.43s. الإطار الأخير عند3.5s يطابق الصورة النهائية المضيئة. `canvas.dataset` يصف `mediaTime` (زمن الساعة) و`frameIndex` (أقرب خلية) و`pose` (الوضعية الكسرية) و`dip` (إزاحة التعليق) و`lightStage` (off→led→headlights). تُحرر الصور والـCanvas الجانبية فور رسم النهاية أو الإلغاء.

التشغيل مرة واحدة في عمر الصفحة. تغيير اللغة أو القائمة أو العودة من الحجز يعرض الصورة النهائية نفسها دون إعادة الساعة أو تنزيل القاعدة والأطالس. تقليل الحركة يعرض الصورة النهائية مباشرة، وتغييره أثناء التشغيل يوقف الحركة. عند فشل تحميل القاعدة أو إحدى صور الأطالس أو إحدى طبقتي الضوء أو غياب Canvas يعود العرض بهدوء للصورة النهائية المضيئة. إخفاء الصفحة يوقف الساعة ويستأنف من النقطة نفسها بعد عودتها؛ تغيير المسار يحرر الموارد والمؤقتات ومستمعي الأحداث ويلغي إطارات الرسم. لا تضف حلقة loop أو تحميل أصول الحركة عند تقليل الحركة. روابط التطبيق والأصول تستخدم الإصدار `20261027-motion` لتجاوز التخزين القديم عند النشر.

مقدمة النصوص تتلاشى إلى الظهور مرة واحدة في عمر الصفحة، ولمعة معدنية واحدة تمر عبر العنوان الرئيسي؛ `heroIntroPlayed` يمنع تكرارهما عند تغيير اللغة أو القائمة أو الرجوع من الحجز. تحويم الأزرار يكبرها إلىscale(1.02) دون تغيير التخطيط. جميع هذه الحركات معطلة عند تقليل الحركة ويظل النص ظاهراً.

حافظ على ظهور عنوان المركز وزري «احجز موعد» و«تواصل معنا» وصف الماركات والسيارة ضمن أول شاشة390×664 فوق شريط الاختصارات. اختبر عرض320px وتخطيط الكمبيوتر قرب760px، واللغتين والمظهرين. لا تضف سطر ماركات آخر داخل السيارة أو بطاقة التتبع التجريبية الكبيرة إلى أول شاشة.

## النشر التلقائي على GitHub Pages

بعد الدفع راقب Actions حتى نجاح build وdeploy، ثم افتح رابط Pages الناتج وافحص الأصول والحجز والأعراض. الرابط المتوقع وحده لا يثبت نجاح النشر. راجع [تعليمات GitHub الرسمية](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) عند تغيير أسلوب النشر. لا توجد إعدادات دومين مخصص أو DNS في هذا المشروع.
