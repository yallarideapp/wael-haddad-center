# دليل صيانة موقع مركز وائل حداد

هذا هو مرجع العمل الأساسي لأي مطور يبدأ من نسخة المستودع. يصف السلوك الحالي والقرارات التي يجب الحفاظ عليها، حتى لو لم يتوفر سجل العمل المحلي أو لقطات المعاينة. آخر تحديث لهذا المرجع: 25 تشرين الأول 2026.

## أين نعدل

`Source/` هو المصدر المعتمد للموقع. عدّل ملفات الموقع فيه فقط، ثم أعد توليد النسخ المشتقة. لا تعدّل `Demo/` أو مجلد التسليم أو ملفات ZIP يدوياً؛ أي تعديل فيها سيضيع عند التغليف التالي.

| الملف داخل `Source/` | المسؤولية |
|---|---|
| `index.html` | نقطة الدخول، بيانات الصفحة، الخطوط، وترتيب تحميل `data.js` ثم `app.js` ثم `admin.js`. |
| `data.js` | الإعدادات والمحتوى والخدمات والأعراض والمراحل والتعليقات، ثم البيانات التجريبية تحت `sample`. |
| `hood-motion.js` | تركيب قاعدة السيارة الثابتة مع إطارات الغطاء الشفافة داخل Canvas وتثبيت النهاية وإدارة الإلغاء والبدائل. |
| `app.js` | القالب المشترك، التنقل، الحجز، الأعراض، التتبع، التقارير، سجل السيارة، التخزين، وإضاءة الواجهة. |
| `admin.js` | لوحة التحكم التجريبية وشاشة الميكانيكي؛ تستخدم الوظائف المشتركة التي يتيحها `app.js`. |
| `styles.css` | التصميم المتجاوب، العربية والإنجليزية، الألوان، وشريط الموبايل وحركة المصابيح. |
| `assets/` | صور التشغيل والشعارات والأيقونة. |
| `tools/package-store.sh` | إنشاء العرض وملفات الرفع والمصدر والتسليم والتحقق منها. |
| `tools/render-car-frames.py` و`tools/car-hood-calibration.json` | إخراج إطارات الغطاء محلياً من بكسلات الفيديو المرجعي فوق جسم الاستوديو الثابت؛ لا تعمل هذه الأدوات في المتصفح أو أثناء التغليف العادي. |
| `tools/delivery-README-AR.md` | قالب دليل التسليم. |
| `tests/` | الاختبارات القابلة للتشغيل؛ راجع [دليل الاختبارات](tests/README.md). |

اقرأ الملفات من القرص مجدداً قبل تعديلها، خصوصاً عند العمل بالتوازي. وثّق أي تغيير في السلوك أو المحتوى المعتمد هنا أو في المستند المناسب، ولا تعتمد على سجل محادثة غير موجود في المستودع.

## المعاينة المحلية

الموقع HTML وCSS وJavaScript عادي، بلا خطوة بناء وبلا سيرفر تطبيق. من جذر المشروع:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory Source
```

افتح `http://127.0.0.1:8765/`. تتطلب هذه الطريقة Python 3. ويمكن فتح `Source/index.html` مباشرة لمعاينة سريعة، لكن استخدم HTTP للفحوص ولثبات سلوك المتصفح. على الماك، يفتح `START-DEMO.command` العرض المولّد إن وجد، وإلا يفتح المصدر.

الخطوط تُحمّل من Google Fonts؛ عند غياب الإنترنت يستخدم المتصفح خطوط الجهاز. النص العريض داخل شريط العرض لا يوسّع صندوق السطر أثناء تحميل وزن الخط، لمنع انزياح الصفحة والسيارة بكسلًا واحدًا. الصور والشعارات اللازمة للتشغيل محلية. أوامر الاختبار وإعداد المتصفح موثقة في `tests/README.md`؛ لا تضف مسارات خاصة بجهاز معين إلى الاختبارات أو الأدلة العامة.

## التغليف والتسليم

من جذر المشروع شغّل:

```sh
bash Source/tools/package-store.sh
```

أو شغّل `UPDATE-PACKAGE.command` على الماك. يحتاج السكربت Bash و`zip` و`unzip`؛ ويفحص صياغة ملفات JavaScript أيضاً إذا توفر Node.js.

المخرجات مشتقة من المصدر:

- `Demo/`: عرض محلي مع البيانات التجريبية.
- `wael-haddad-hostinger-upload.zip`: ملفات الموقع العام، و`index.html` في جذر الأرشيف.
- `WaelHaddad-website-source.zip`: مصدر قابل للصيانة.
- `WaelHaddad-complete-with-demo/` و`WaelHaddad-complete-with-demo.zip`: التسليم الكامل الذي يحتوي النسخ السابقة وأدلتها.

يوضع أرشيفا الرفع والمصدر داخل بنية التسليم. راجع رسالة النجاح النهائية للسكربت بدلاً من افتراض وجودهما في جذر المشروع. ملفات التشغيل المعتمدة محددة في مصفوفة `RUNTIME`؛ عند إضافة أصل مطلوب في المتصفح أضفه إلى تلك القائمة أيضاً.

على الماك يخفي السكربت الملفات الداخلية بعَلَم Finder، ليبقى مجلد التسليم وملف ZIP الكامل ظاهرين. هذا لا يحذف الملفات ولا يمنع قراءتها. يمكن إظهار الملفات المخفية بواسطة `Cmd+Shift+.`. الملفات المولّدة والمخرجات المؤقتة لا تُرفع إلى المستودع؛ يمكن إعادة إنتاجها من المصدر. مؤقت الفيديو وصورة قاعدة السيارة وأطالس طبقات الغطاء الشفافة وصورتا الفتح والإغلاق هي أصول الواجهة؛ الصورة المغلقة المركبة تكفي للعرض الثابت عند تعذر التشغيل. حزمة المصدر تتضمن صورتي الاستوديو بصيغة WebP وأطلس الغطاء المرجعي `hood-reference.webp` وسكربت إخراج الإطارات ومعايرته لإعادة إنتاج الأصول محلياً. النسخة الأصلية PNG عالية الجودة اختيارية؛ لا تحتاجها حزمة التشغيل العامة.

## الفرق بين العرض والموقع العام

يجب أن يبقى هذا السطر في `data.js` بالحروف والمسافات نفسها:

```js
  mode: 'demo',
```

سكربت التغليف يحوّله إلى `live` في نسخة الرفع فقط. لا تغيّر المصدر إلى `live` لتجهيز تسليم.

| الحالة | `demo` | `live` |
|---|---|---|
| الخدمات والعرض والأعراض والتواصل والحجز | متاحة | متاحة |
| أمثلة السيارات والحجوزات وسجل الصيانة | تُنشأ من `sample` وتُعلّم بأنها أمثلة | لا تُنشأ في الحالة التشغيلية ولا تظهر في الواجهة |
| التتبع والتقارير والسجل والأدمن والميكانيكي | تجربة محلية | المسارات محجوبة |
| التخزين | `localStorage` بالمفتاح `wh-demo-v1` | تخزين المتصفح بالمفتاح المنفصل `wh-live-v1` |
| وصول الطلب إلى المركز | يحتاج المستخدم إرسال رسالة واتساب | يحتاج المستخدم إرسال رسالة واتساب |

إخفاء صفحات العرض في `live` ليس نظام صلاحيات أو حماية بيانات. البيانات تحت `sample` أمثلة عامة وليست سجلات زبائن حقيقية؛ لا تضع أي سجل حقيقي أو سر داخل JavaScript. لا تعتمد على حجب المسارات لإخفاء محتوى الملف المصدر.

لوحة التحكم بلا كلمة سر في العرض، وتعديلات الأسعار والخدمات والحجوزات والموافقات تبقى في ذلك المتصفح. تغيير بيانات `data.js` لا يضمن استبدال إعدادات محفوظة سابقاً في `localStorage`؛ عند التحقق من القيم الافتراضية استخدم سياق متصفح جديداً أو إعادة ضبط بيانات العرض. يدعم الكود فشل التخزين أو حظره، ويعرض رسالة داخل الصفحة عند تعذر الحفظ.

## الحجز وواتساب: ثوابت وظيفية

الحجز ينتهي بصفحة تلخيص وزر يفتح رابطاً من الشكل `https://wa.me/962...` مع رسالة جاهزة يُرمّز نصها داخل الرابط وتحتوي تفاصيل الطلب. الرقم الافتراضي حالياً `0795866455`، ويتحول إلى `962795866455` في الرابط. إنشاء الطلب في المتصفح أو فتح صفحة التلخيص لا يرسل رسالة تلقائياً؛ المستخدم يرسلها من واتساب، والمركز يؤكد الموعد بالرد. لا يوجد استقبال مركزي للحجوزات في النسخة الحالية.

**لا تُعد رسم زر تثبيت الحجز أثناء الكتابة.** مع أحداث `input` و`change` تُحدّث المسودة و`#sum-body` فقط. إعادة بناء النموذج أو ملخصه الكامل قد تستبدل الزر بين نهاية الكتابة ولمسة الإرسال، فتضيع اللمسة. حافظ على هذا السلوك عند إضافة تحقق أو حقول أو تحسينات للملخص.

- الأرقام العربية `٠١٢٣٤٥٦٧٨٩` والفارسية `۰۱۲۳۴۵۶۷۸۹` تُطبّع إلى أرقام عادية.
- أرقام الجوال الأردنية المقبولة تطابق `^07[789]\d{7}$` بعد التطبيع. يدعم التطبيع بادئتي `962` و`00962`.
- بحث اللوحة يستخدم الأرقام بعد إزالة الفواصل والمسافات والعلامات، لذلك يجب أن يتطابق الإدخال بالأرقام العربية مع اللوحة التجريبية نفسها.
- أنشئ روابط الأجزاء دون شرطة مائلة: `#book` و`#book-svc-oil` و`#book-sym-brakes` و`#report-J1024` و`#job-J1024`. هذا يحافظ على الروابط العميقة في الاستضافات التي تغيّر `/` داخل الجزء.
- التأكيدات والأخطاء داخل الصفحة. لا تستخدم `alert()` أو `confirm()` أو `prompt()`.
- حافظ على فصل اختيار العَرَض `brakes` عن نص تسميته؛ تغيير الاسم الظاهر لا يغيّر المعرّف أو مستوى الاستعجال أو النصيحة.

## اللغة والاتجاه والمظهر

العربية هي الافتراضية باتجاه RTL، والإنجليزية متاحة من زر اللغة باتجاه LTR. اختيار اللغة محفوظ بالمفتاح `wh-lang`. يستخدم `app.js` الدالتين `tr(ar, en)` للنصوص و`L(object, key)` للحقول المنتهية بـ`Ar` و`En`. حافظ على تعيين `lang` و`dir` على عنصر `html` عند إعادة الرسم.

المظهر يتبع `prefers-color-scheme`، وتدعم CSS أيضاً تعيين `data-theme="light"` أو `data-theme="dark"` على الجذر. لوحة الموقع بني دافئ وبيج: الواجهة الأولى بني شوكولاتة `#302118` في المظهرين، مع نص وأزرار كريمية؛ بقية الأقسام بيج رملي وأسْطح كريمية في الفاتح، وبني داكن وأسْطح جوزية ونص بيج في الغامق. متغيرات `--bg` و`--surface` و`--sunk` تضبط الأقسام والبطاقات والنماذج؛ ومتغيرات `--hero-*` تضبط لون الواجهة ونصوصها وأزرارها. لا تصبغ جسم السيارة أو الشعارات أو طبقة LED بفلاتر الألوان عند تعديل اللوحة. اختبر اللغتين والمظهرين، ولا تفترض أن تغيير اللون يؤثر فقط في العربية.

الأسماء في صف الماركات إنجليزية في اللغتين، بالترتيب `Audi` ثم `Volkswagen` ثم `Porsche`، مع شعار كل اسم. القائمة `.hero-specialism` لها `dir="ltr"`؛ لا تعكس ترتيب العناصر مع RTL. صور الشعارات لها `alt=""` لأن الاسم مكتوب بجانبها، لتجنب تكراره لقارئ الشاشة. لا تضف مقدمة «متخصصين» أو `Specialists` إلى هذا الصف.

ملفات الشعارات الرسمية محفوظة كما هي في المصدر؛ يعرض شعار Audi بإنهاء كروم معدني ثلاثي الأبعاد وشعار Volkswagen بالقاعدة الدائرية الزرقاء الملكية والكروم الأصليين مباشرة فوق الخلفية البنية، ويحتفظ شعار Porsche بألوان درعه الأصلية دون فلاتر. العناوين فوق الأسطح الداكنة بلون شامبانيا دافئ `#E8CFA4` مع لمعة معدنية هادئة، والعنوان الفرعي في الواجهة بلاتيني ناعم `#DDD4C7` والنص الثانوي `#CFC8BE`؛ عناوين الأسطح البيج في الوضع الفاتح تبقى برونزية داكنة للتباين. خلفية السيارة تتضمن هالة إضاءة دافئة في `.hero-visual::before`، وإضاءة المصابيح مدمجة في الإطار النهائي المعد محلياً. صور السيارة وطبقات الغطاء شفافة خارج حدودها، وتظهر خلفها ألوان الموقع نفسها دون مستطيل أو قناع تلاشي. ظل أرضي ناعم في `.hero-car::before` يثبت العجلات. الخطوط والأحجام وتوزيع النص لم تتغير.

## الواجهة الأولى وحركة غطاء السيارة

السيارة صورة توضيحية وليست توثيقاً لسيارة زبون أو تجهيزات المركز. يستخدم العرض جسم السيارة من الصورة الأصلية الحادة عالية الدقة، مع تفاصيل حجرة المحرك من أصل توضيحي لحالة الفتح. يبقى الجسم والعجلات والكاميرا ثابتة، وتأتي بكسلات الغطاء المتحرك من إطارات الفيديو السابق نفسه، ثم تضاء المصابيح بعد الإغلاق. يُعزل الغطاء بحدود منحنية متتبعة عبر الإطارات ويُحاذى محلياً مع فتحة الجسم الأصلي؛ لا يُعاد تحريك صورة مسطحة أو تبديل وجهيها. يحتفظ الغطاء بتتابع نزوله المصور مع ملاءمة المنظور للصورة الأصلية، ولذلك لا يوصف الناتج بأنه نسخ مطابق لكل بكسل في الفيديو أو فيديو جديد عالي الدقة. لا يحتاج التشغيل إلى قص CSS أو مجسم أو إعادة إسقاط هندسي داخل المتصفح.

| أصل التشغيل | الوصف |
|---|---|

### إعادة إخراج الإطارات محلياً

`tools/render-car-frames.py` يقرأ `tools/car-hood-calibration.json` وأطلس `assets/hood-reference.webp` وصورة الفتح `assets/car-studio-open.webp` بدقة1672×941. يفضل أصل الجسم `assets/coupe-studio-master.png` إن وجد محلياً، وإلا يستعمل `assets/coupe-studio.webp` بالحجم نفسه والمضمن في حزمة المصدر. يحاذي الجسم بإزاحة(1،110)بكسل، ويستبدل حدود لوحة الغطاء الكاملة بتفاصيل الحجرة فقط من صورة الفتح، مع إبقاء الجسم خارجها من الصورة الأصلية. حد الجانب القريب يتبع المفصل عند(1054،432)حتى الركن الأمامي(832،531)، ولا يتبع خط اللمعة الداخلي. المفصلة البعيدة عند(491،417)، والركن الأمامي البعيد عند(130،521).

يحفظ أطلس التحضير47خلية600×300 بترتيب6أعمدة×8صفوف؛ تؤخذ كل خلية من الإطار المحسن السابق1080×600 عند الإزاحة(80،16). تصف المعايرة تحويل محاذاة ثابتاً من إحداثيات الفيديو720×400 إلى لوحة الجسم الأصلي، وتسعة حدود يدوية منحنية للغطاء. يعاد توزيع كل حد إلى128نقطة، ثم تُستوفى الحدود بين المواضع المرجعية المتباعدة ستة إطارات، وتُعزل بكسلات الغطاء نفسها بحافة ناعمة. لا يُحسب مسار دوران جديد ولا لحظة تبديل لوجهين. إطارات0..46 تتبع الغطاء السابق خلال نحو1.92s، ويُطابق الإغلاق في44..46 مع لوحة الصورة الأصلية الحادة، ثم يضيف الإطار47 إضاءة LED محلياً. يخرج السكربت القاعدة والأطالس والصورتين المركبتين، مع شفافية حقيقية وخلفية الموقع الظاهرة خلفها. دقة تفاصيل الجسم مصدرها1672×941؛ تفاصيل الغطاء المتحرك تظل محدودة بالفيديو الأصلي ذي العرض720px، ولا يخلق تكبيرها تفاصيل تصوير جديدة.

تحتاج إعادة إخراج الإطارات فقط إلى Python3 مع Pillow وnumpy وOpenCV. هذه تبعيات تحضير محلية اختيارية، لا تُشحن في الموقع ولا تحتاجها عملية التغليف العادية. من جذر المشروع، بعد توفيرها:

```sh
python3 Source/tools/render-car-frames.py
```

يمكن تحديد صورة الجسم بواسطة `--body-photo /absolute/path/to/image.png`، ومجلد مراجعة خارجي بواسطة `--review /absolute/path/to/review`. الخيار `--reference-frames /absolute/path/to/frames` يستورد48إطار PNG محسناً سابقاً بدلاً من أطلس المرجع المضمن؛ الاستعمال العادي لا يحتاج هذه الملفات المحلية. يجب أن تبقى مدخلات الاستوديو1672×941. حزمة المصدر تتضمن السكربت والمعايرة وصورتي الاستوديو وأطلس المرجع بصيغة WebP لإعادة الإنتاج؛ أصل PNG اختياري لتحسين جودة المصدر. عند تعديل المعايرة راجع الفتح وتسع وضعيات إغلاق والنهاية، وحدود الرفارف والشبك والمفصلات، وثبات بكسلات الجسم والعجلات، قبل اعتماد الإطارات. إخراج الإطارات محلي؛ لا يحتاج إلى خدمة فيديو خارجية.

`heroCar()` يحتفظ بإطار ثابت بنسبة720/400، عرضه100% وبحد أقصى520px حسب التصميم المعتمد. `rs5SourceVideo` مصدر مخفي بصرياً بحجم1px (وليس display:none)، و`rs5HeroCanvas` بقناةalpha يرسم القاعدة الثابتة أولاً ثم خلية الغطاء المحددة بالتوقيت. لا يوجد تحريك أو تلاشي لعنصر السيارة أو قناع على إطارها. الظل الأرضيCSS مستقل. صور الاستوديو ومدخلات التحضير لا تدخلRUNTIME؛ القاعدة المركبة هي أصل الجسم المطلوب وقت التشغيل.

`startHeroLights()` يحتفظ باسمه لتوافق بقية التطبيق، ويبدأ ساعة الفيديو. `WHHood.create()` ينتظر فك القاعدة والأطالس الأربعة وأول إطار مؤقت، ثم يعرض الفتح المركب؛ لا يظهر إطار مغلق ثم يقفز للفتح. عند ظهور55% من الإطار عبر IntersectionObserver، ينتظر300ms مرئية ثم يشغّل الساعة المكتومة. يستخدم requestVideoFrameCallback حيث يتوفر، وrequestAnimationFrame بديلاً. عند النهاية يوقف الفيديو ويحفظ آخر تركيب مفكوك فعلياً (زمنه duration−1/24 بينما currentTime قد يساوي duration) ثم يثبته دائماً. إذا لم تكن النهاية مفكوكة بعد، يستخدم طلب توقيت النهاية وفكها بديلاً؛ لا يعيد طلب seek دون حاجة بعد نهاية تشغيل طبيعية. `data-phase` ينتقل loading→open→closing→complete و`data-frame` يحدد video أوposter؛ `canvas.dataset.mediaTime` يصف التوقيت و`frameIndex` يحدد الخلية0..47. يُثبت الإطار47 حتى نهاية مؤقت2.5s. تُحرر صور القاعدة والأطالس فور رسم النهاية أو الإلغاء؛ الأطالس وحدها تقارب124MB مفكوكة أثناء التشغيل، دون الاحتفاظ بها بعده.

التشغيل مرة واحدة في عمر الصفحة. تغيير اللغة أو القائمة أو العودة من الحجز يعرض الصورة النهائية نفسها دون إعادة الساعة أو تنزيل القاعدة والأطالس. تقليل الحركة يعرض الصورة النهائية مباشرة، وتغييره أثناء التشغيل يوقف الحركة. عند حظر التشغيل التلقائي أو فشل تحميل الفيديو أو القاعدة أو إحدى صور الأطالس أو غياب Canvas يعود العرض بهدوء للصورة النهائية المضيئة. إخفاء الصفحة يوقف المؤقت والتشغيل ويستأنف بعد عودتها؛ تغيير المسار يحرر المصدر والموارد والمؤقتات ومستمعي الأحداث ويلغي إطارات الرسم. لا تضف حلقة loop أو autoplay أو تحميل أصول الحركة عند تقليل الحركة. روابط التطبيق والأصول تستخدم الإصدار `20261025-video-hood-hq` لتجاوز التخزين القديم عند النشر.

مقدمة النصوص تتلاشى إلى الظهور مرة واحدة في عمر الصفحة، ولمعة معدنية واحدة تمر عبر العنوان الرئيسي؛ `heroIntroPlayed` يمنع تكرارهما عند تغيير اللغة أو القائمة أو الرجوع من الحجز. تحويم الأزرار يكبرها إلىscale(1.02) دون تغيير التخطيط. جميع هذه الحركات معطلة عند تقليل الحركة ويظل النص ظاهراً.

حافظ على ظهور عنوان المركز وزري «احجز موعد» و«تواصل معنا» وصف الماركات والسيارة ضمن أول شاشة390×664 فوق شريط الاختصارات. اختبر عرض320px وتخطيط الكمبيوتر قرب760px، واللغتين والمظهرين. لا تضف سطر ماركات آخر داخل السيارة أو بطاقة التتبع التجريبية الكبيرة إلى أول شاشة.

## النشر التلقائي على GitHub Pages

سير العمل `.github/workflows/pages.yml` ينشر نسخة `live` عند push إلى `main`، أو عند تشغيله يدوياً. إعداد Pages في المستودع يجب أن يكون **GitHub Actions**. يستخدم إجراءات GitHub الرسمية وبأذونات قراءة المصدر ونشر Pages وطلب رمز هوية للنشر فقط؛ لا يوجد مفتاح نشر مخزن في المشروع.

`bash Source/tools/build-pages.sh` يشغّل سكربت التغليف، ثم يستخرج ZIP الرفع الذي أُنشئ إلى `.pages-output/`. هذا المجلد مؤقت ومُستثنى من Git؛ لا تعدّل محتواه يدوياً ولا ترفع Source نفسه كجذر Pages، لأن ذلك سينشر وضع العرض. المسارات إلى CSS وJavaScript والصور نسبية، وروابط التنقل تستخدم hash، ولذلك يعمل الموقع تحت مسار اسم المستودع. عند إضافة أصل تشغيل حدّث `RUNTIME` في سكربت التغليف قبل الدفع.

بعد الدفع راقب Actions حتى نجاح build وdeploy، ثم افتح رابط Pages الناتج وافحص الأصول والحجز والأعراض. الرابط المتوقع وحده لا يثبت نجاح النشر. راجع [تعليمات GitHub الرسمية](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) عند تغيير أسلوب النشر. لا توجد إعدادات دومين مخصص أو DNS في هذا المشروع.
